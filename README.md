# Bharat Institute of Technology

BIT course catalogue and institute certificate registry for Vercel.

## What changed
- Detailed entry guidance, tools, four-module teaching plans, learning outcomes, project and assessment guidance for all 18 proposed courses.
- Full downloadable course outlines; existing colour scheme, 3D hero and responsive pages retained.
- Public QR verification reads the online register, including revocation status, without requiring a login.
- Server-only password verification, short-lived HTTP-only sessions and login rate limiting.
- Authenticated issuing, duplicate-number protection, revoke/restore and PNG/PDF export.
- QR images are generated by the same application; certificate details are not sent to an external QR service.

## Required production configuration

The previous application was a browser-only demo. This version deliberately does not trust local storage, client-provided certificate details or the old public signing salt.

Before deploying, connect a persistent Upstash Redis database to the Vercel project and set these server-only environment variables:

| Variable | Purpose |
| --- | --- |
| `ADMIN_PASSWORD` | Administrator login password; never place it in frontend files |
| `UPSTASH_REDIS_REST_URL` | Database REST endpoint |
| `UPSTASH_REDIS_REST_TOKEN` | Database REST write token |
| `SITE_URL` | Exact production origin, such as `https://bitghosi.vercel.app` |

Use the actual production domain for `SITE_URL`. Admin mutations reject other origins. A preview needs its own matching origin and preferably a separate database. Do not add `NEXT_PUBLIC_` or `VITE_` prefixes to secrets. Missing configuration produces an honest unavailable message and prevents issuing or false verification.

Vercel: Framework preset **Other**, repository root directory, build `npm run build`, output `public`, production branch `main`. The `/api/registry` Node.js function is deployed from `api/registry.js`. `vercel.json` specifies build and output settings.

## Existing certificates

Old browser-only records are not automatically imported or treated as authentic. The administrator must review original evidence and reissue certificates in the online register. Old payload links are used only to extract a certificate number; verification still requires a matching server record. Reprint old certificates with the new QR after reissuing.

Certificate verification is public to anyone holding its number/link. Only issue the student name, course, date and authorised signatory intended for public verification. Do not add addresses, birth dates or contact details. Random suggested certificate numbers reduce casual enumeration.

## Validation

```sh
npm ci
npm test
npm run build
```

Automated tests cover unauthorised/forged access, cross-origin writes, issue/verify/revoke/restore, duplicate prevention, QR generation, invalid dates, login throttling, logout and password rotation. Tests use a simulated Redis command interface; live database and Vercel deployment verification remain required after configuration.

After deployment: sign in, issue an explicitly labelled test certificate, scan its QR from a different device, revoke it and confirm the public page changes. Check both PDF and PNG before issuing real certificates.

## Content status

Course durations and teaching plans are proposed, not confirmed institute offerings. Fees and batch dates must be supplied by the institute. No external accreditation, qualification equivalence or employment guarantee is represented.
